## 多关键词配置与启动（当前入口）

正式实现位于项目本地 `src/`，根目录的 `crawler.py` 仅兼容原来的单任务命令。已有 `.profiles/`、`.state/` 和历史输出保留原位置，不重新登录、不搬动旧账号资料。

编辑根目录 `tasks.json`：顶层是任务数组，已预留三个任务，`keyword` 按要求留空，每项 `target_count` 为 15。全部关键词填好后才允许启动；后面的任务配置错误也会在打开浏览器之前拒绝整批。各项字段：

| 字段 | 含义 |
| --- | --- |
| `keyword` | 搜索关键词，不能为空、不能重复 |
| `target_count` | 该关键词目标完整正文数量；跳过的不计入，已有完整缓存计入 |
| `wait.min_seconds` / `max_seconds` | 笔记／搜索轮次之间的短等待范围，默认 10–60 秒 |
| `wait.long_probability` | 附加长等待概率，默认 0.05 |
| `wait.long_min_seconds` / `long_max_seconds` | 长等待范围，默认 300–600 秒 |
| `budget.max_requests` | 每项任务单轮资源请求上限，默认 15000 |
| `budget.task_requests` | 同一关键词跨次资源请求上限，默认 15000 |
| `budget.daily_requests` | 所有关键词和运行共享当日计数，默认 20000 |
| `budget.total_requests` | 历史累计上限，默认 null，即只统计 |
| `budget.max_minutes` | 每项任务本轮最长分钟数，默认 180 |

每次点击、输入、提交、滚动和导航前仍按 1–5 秒范围随机等待，不由任务的短等待字段替代。三个任务按顺序复用 `check_20261030` 登录目录；遇到异常、预算、停止锁或当前任务未达到目标就停止整批，不继续下一项、不自动解除停止锁。单项完整缓存命中时直接导出。各关键词之间可能出现相同笔记，同一篇在各自关键词目标内各计一次，不保证全批次 45 篇互不重复。

## 实时观察与单次验证

程序本质上是 Playwright 控制 Edge 的浏览器自动化。默认不带 `--headless`，浏览器窗口可见，可观察输入、搜索、点击笔记和返回等动作。终端会立即打印带时间的步骤，并同步写入本轮归档目录的 `actions.jsonl`。动作日志不记录 Cookie 或 URL 的 token 查询参数。

`--slow-mo 500` 在 Playwright 的浏览器操作间增加约 500 毫秒慢放，便于观察；它不替代 10–60 秒的浏览间隔，也不能保证降低账号风险。发现异常时，在终端按 Ctrl+C 停止并保留进度。

优先复用已保存的登录状态，不带 `--login` 就不会主动要求扫码。已确认 `.profiles/check_20261030/Default/Network/Cookies` 文件存在，但不通过读取或输出 Cookie 值来推断登录是否仍有效。如果网站确认状态失效，停止后可在同一个目录中显式加 `--login` 手动重新登录；不会自动切回旧账号。以下命令仍受现有停止锁约束，不会自动解除。账号准备完成后，可进行一次完整验证：

```powershell
python -X utf8 crawler.py --profile check_20261030 --keyword "你要测试的搜索词" --test-once --slow-mo 500
```

`--test-once` 使用独立测试任务（不重置全局状态），固定目标 1 条且启用正文采集。最多提交一次关键词搜索，不自动滚动，按既定跳读概率选最多一篇打开；候选不足或遇到限制即结束，不再补搜。该模式要求从本次保存的文件解析到正文，不能仅靠历史正文缓存判为成功。执行顺序为搜索、打开一篇、保存实际 HTML／JSON 与渲染 HTML、从文件解析、更新 CSV 和报告。第一次手动登录所需的请求也计入预算。

本轮修改仅进行离线测试，尚未使用新账号执行上述在线验证。终端日志和浏览器窗口是两个观察渠道，不提供聊天内的实时浏览器视频流。

## 任务标识与正文来源修复

通过 `--url` 指定搜索页面时，任务标识会保留关键词和筛选等查询参数，并对参数顺序规范化；访问 token、来源追踪等参数不参与身份标识。同一笔记更换 token 仍复用缓存。新版搜索 URL 任务使用 v2 标识，不会自动合并旧版可能混淆关键词的 URL 任务；已有 `--keyword` 任务保持不变，旧数据不删除。

正文与详情归档路径成组更新，后续搜索摘要不会覆盖已有正文的详情来源。CSV 中 `source_archive` 等列对应正文／记录来源，`search_source_archive`、`search_original_html_path`、`search_rendered_html_path`、`search_raw_json_paths` 单独记录该搜索任务下的发现来源。历史正文没有详情归档时保持空白，不用搜索 HTML 冒充。

`--limit` 是目标导出／抽样笔记数，包含缓存命中，不表示每次新增这么多条。使用 `--details` 时，已有足够完整缓存可直接导出；需要联网时按下文权重选择条目，候选不足才继续搜索加载，因此可能需要发现多于 limit 的列表记录。不同关键词分别保存任务关联，但相同笔记的已完成正文跨关键词复用。缓存目前不会自动刷新正文；如确需新版本，可先离线检查旧结果再决定是否另行采集。

## 访问顺序与等待

搜索及详情现在先归档、后离线解析，目录和抽样规则见下文。搜索时打开探索页，在网站搜索框输入关键词并提交。搜索页已有可见笔记链接时点击进入，优先通过页面关闭按钮或浏览器返回继续；缓存已完整的笔记不会再次访问。断点恢复时，如果当前页没有对应链接，才使用保存的笔记 URL，报告标记为 `saved_url_resume`；真实链接点击标记为 `page_link_click`。优先保留网页上的真实链接及查询参数。

这使用正常网页交互，但不能保证完全复现人工浏览的请求顺序：浏览器缓存、异步上报、页面实现等都会影响请求。为保证请求预算可控，程序阻止 Service Worker，由路由检查应用页面的 HTTP(S) 请求，不做鼠标轨迹或浏览器特征伪装。

默认每篇访问结束后记录 **均匀随机 10–60 秒**间隔，另有 **5% 概率附加均匀随机 300–600 秒**等待。滚动加载也遵守短等待及长等待策略。最后一篇结束时仅保存等待截止时间，程序可直接退出；下次联网前补足剩余等待。等待期间每秒检查停止状态、时长预算，支持 Ctrl+C。随机等待发生在页面操作之间，不会把页面自身的每个资源请求都变为间隔发送。

```powershell
python -X utf8 crawler.py --profile research_02 --keyword "西安三日游" --limit 10 --details --min-wait 10 --max-wait 60 --long-probability 0.05 --long-min 300 --long-max 600
```

## 预算与停止锁

默认预算只是操作上限，不是经过验证的安全阈值：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--max-requests` | 15000 | 本轮最多允许发送的页面上下文 HTTP(S) 请求尝试 |
| `--daily-requests` | 20000 | 当日本地累计请求上限 |
| `--task-requests` | 15000 | 同一关键词或 URL 任务跨次累计请求上限，从本版本开始统计 |
| `--total-requests` | 不限制 | 历史总量默认仅统计；显式填写该参数仍可启用历史上限 |
| `--max-minutes` | 180 | 本轮联网流程时长预算，包含等待和登录时间 |

默认目标改为 45 篇，默认采集正文；`--limit` 可以更改目标，`--no-details` 可以只采集摘要。`--test-once` 仍强制只测试一篇。任务预算键沿用现有关键词／URL 归一化规则，不受测试时间戳、账号目录或导出数量变化影响；不同关键词分别计任务预算，但共享当日累计量。旧的 1928 次历史／当日计数不清零，旧数据没有可靠的任务级归属，因此不回填新任务计数。

搜索默认最多 30 轮，可用 `--search-rounds` 调整；连续三轮无新增笔记会结束滚动，仅处理已发现并抽中的条目。未取得足够数量时报告 `partial_target`，不会把少于 45 篇的完整正文当作目标已完成。报告记录本轮预算、目标和该任务累计请求量；预算修改不会解除已有停止锁。

复用当前登录账号执行 45 篇任务的命令（本文档不会执行此命令）：

```powershell
python -X utf8 crawler.py --profile check_20261030 --keyword "广东旅游景点" --limit 45 --details
```

当前续采以正文完整为完成标准：已有正文但缺图的历史条目仍跳过，不会因新开启翻图功能自动重访。评论按已加载数据归档，不能保证完整评论；没有可展开回复的笔记无法验证展开点击。浏览器路由会影响 HTTP 缓存，且禁用 Service Worker，因此加载过程与手工浏览并非完全一致；加载诊断应保留这些条件用于排查。

请求发送前先计数、落盘。包含文档、脚本、图片、第三方资源和失败的请求尝试，不只计笔记；应用页面之外的浏览器内部流量、WebSocket 消息不在该计数范围。升级前请求量无法追溯，历史导入不会伪造访问计数。当日按系统本地日期统计，请保持电脑时区为中国标准时间。

达到任一预算，或收到小红书文档/XHR/fetch 的 403、429、限制提示、验证信息及未识别的接口失败时，停止并持久化停止锁。详情异常或正文仍缺失也停止整轮，不继续尝试下一篇。达到时限后不再允许新请求；已在执行的浏览器调用需返回或超时后关闭，在途请求无法撤回。预设预算也可能在正常资源加载中耗尽，此时应查看报告而非盲目放大阈值。

```powershell
python -X utf8 crawler.py --status
python -X utf8 crawler.py --stop "收到平台账号警告，暂停自动访问"
```

停止锁跨运行、跨账号目录生效。缓存导出和离线解析仍可使用，但不会继续联网。确认停止原因并自行决定恢复后，必须单独运行解除命令；该命令本身不启动采集：

```powershell
python -X utf8 crawler.py --clear-stop "已检查停止原因并决定恢复"
```

解除操作会留下审计记录，**不会重置预算和剩余等待**。累计预算已满时，解除锁后仍会停止；若确需调整操作上限，应显式传入预算参数。不要用删除数据库或切换状态目录的方式绕过停止记录。

缓存、请求计数、停止原因、随机等待截止时间都在 `.state/state.sqlite3`；每次取得数据即提交，Ctrl+C 后可以继续。操作系统文件锁防止多个实例同时运行，进程退出后自动释放。强制终止不保证输出报告完成，但已经提交的缓存和计数保留。

## 离线解析

不启动浏览器、不执行保存网页的脚本、不下载资源；即使存在停止锁也能运行。支持旧导出的 JSON/CSV、接口响应 JSON、保存的 HTML，以及手动提供的 TXT/MD 正文：

```powershell
python -X utf8 crawler.py --offline "output/notes_20261028_221746.json" --keyword "旅游规划" --limit 10 --details
python -X utf8 crawler.py --offline "手动保存的笔记.html" "手动整理的正文.txt" --keyword "杭州景区攻略" --limit 20 --details
```

JSON/CSV 中包含笔记 ID 时保留原 ID。HTML 优先读取初始化状态、`#detail-desc` 和 canonical 链接；HTML 不符合这些结构时可能提取到 0 条，不把整个页面的菜单、评论当作正文。无 ID 的 HTML/TXT/MD 使用内容哈希生成 `offline-...` ID，仅用于本地去重，不作为平台笔记 ID。TXT/MD 不自动推断作者、互动数据或发布时间。

## 原始响应、HTML 与实时 CSV

用户已选择“不额外访问”。程序只保存浏览器本次实际收到的文档 HTML／JSON 响应，不为取得独立 HTML 再打开一次 URL。搜索结果和笔记正文分目录归档：

```text
output/
  archive/
    本轮时间/
      search/
        0001/                 # 探索入口响应（manifest.kind=entry，不纳入关键词结果）
        0002/                 # 搜索结果阶段；后续滚动各有独立目录
          response_0001.json  # 实际收到的原始 JSON 响应正文
          response_0002.html  # 仅当本阶段实际返回 HTML 文档时存在
          rendered.html       # 当时 DOM 序列化后的 HTML，不是原始响应
          state.json          # 本机网页内存状态导出，不是接口原始响应
          links.json          # 页面链接导出
          manifest.json       # 响应来源 URL、类型、哈希、阶段及笔记 ID
          parsed.json         # 从上述文件解析得到的记录
          parse_report.json   # 本地解析结果及格式不兼容提示
      posts/
        笔记ID/
          0003/               # 同样保存该笔记阶段的响应、HTML 及解析结果
  checkpoints/
    搜索词_任务哈希.csv         # 每轮搜索／每篇笔记解析后更新，包含全部发现条目
```

以上文件是类型示例，实际 response 编号和数量随网页变化。原始响应文件由 `response.body()` 提供的 bytes 直接写入，不格式化、不注入代码；浏览器可能已解除传输压缩，所以它不是 TCP 包、也不等于压缩后的线上字节。原始文件可能在页面后台请求完成后继续增加，`parsed.json` 对应一次解析时点，日后可离线重解析。

单页应用经常只返回 JSON，然后更新 DOM。此时某篇笔记没有独立的原始 HTML 文档，`original_html_path` 留空；仍保存实际收到的 JSON 和 `rendered.html`。不会把入口页 HTML 或渲染后的 HTML 冒充该笔记的原始响应。入口阶段单独标为 entry，避免把推荐笔记混入关键词搜索。

明确的工作顺序：**取得页面 → 原始响应落盘 → 保存渲染 HTML／状态 → 从本地文件解析 → 更新缓存及 CSV → 开始约定随机等待 → 下一次浏览操作**。正文提取不再直接在接口回调内入库。解析本身耗费的时间在随机等待之前，不虚构额外“解析延时”。页面打开期间仍可能发生网站的后台请求；本地解析和等待不会冻结网站脚本。

CSV 包含关键词任务、发现顺序、标题、URL、正文、抽样状态、步长及归档路径。CSV 是便于查看的实时清单；内部数据库继续负责去重、任务关联、抽样断点、请求预算和停止锁。编辑或删除 CSV 不会自动改动内部状态；需要导入时使用 `--offline`。历史采集没有保存原始 HTML，不能从现有正文还原；直接命中旧缓存时不会为了补 HTML 重新访问。

若 CSV 正被 Excel 独占，原子更新可能失败；此时采集会停止、已保存原始文件及缓存仍保留，请关闭文件后检查停止原因再恢复。

## 按顺序概率跳读

`--details` 联网补正文时，按照搜索结果首次发现的顺序，从当前位置抽取下一次前进步长：

| 前进条数 | 概率 | 含义 |
| --- | --- | --- |
| 1 | 60% | 浏览下一条 |
| 2 | 20% | 跳过一条，浏览第二条 |
| 3 | 10% | 浏览第三条 |
| 4 | 5% | 浏览第四条 |
| 5 | 5% | 浏览第五条 |

例如已浏览第 2 条，抽中步长 3，则跳过第 3、4 条，浏览第 5 条。第一次从“第 0 条”开始抽签。每次独立抽签，有限样本不会恰好符合比例。平均前进步长为 1.75；边界、重复结果和缓存会影响实际访问数量。

抽样计划会保存 selected、skipped 和尚未满足的目标位置。当前候选不足时，等待加载更多结果，不重新抽签选尾部；重启继续原计划，不自动补看被跳过的条目。CSV 标明 selected_pending、selected_complete、skipped、discovered、cached_complete。已完整的缓存不会重复访问；无须联网的缓存导出不重新抽样。`--limit 10` 是目标选中条数，遇到预算或结果不足可能少于 10 条。

## 被动保存浏览器收到的图片

图片响应回调现在会把小红书／xhscdn 图片域名实际返回的 HTTP 200 图片正文直接写入本轮 `received_images/`，以 SHA-256 去重，并用 index.jsonl 记录来源。不会调用 requests、额外 fetch、重放图片 URL，图片保存模块本身不补发下载请求；新默认的浏览动作会正常点击轮播箭头，触发网站自身的懒加载。搜索封面已收到的图片也可以复用于相应笔记。

详情归档的 `images/` 内保存与该笔记 image_list 匹配的图片和 index.json。通过原 URL 或相同 CDN 资源 ID 匹配，保留实际收到的预览／正文等版本，不能把缩略图称为原图。清单包含 expected_count、saved_count、missing_count，未收到的图片标为 not_received。CSV 新增 image_count、saved_image_count、image_manifest。浏览器关闭后会再从本地图片池匹配一次，不会发起下载。received_images 中可能还包含页面头像、图标等资源；笔记 images 目录只复制与该笔记列表匹配的资源。

## 当前浏览偏好：全部配图与随机展开回复

默认启用 `--browse-images`、`--expand-comments`；可用 `--no-browse-images --no-expand-comments` 临时关闭。

图片：根据当前笔记的配图总数，逐张点击实际轮播箭头浏览，每次翻图前独立均匀随机等待 1–5 秒。等待当前图片加载成功，保存每张的渲染 HTML 快照，再浏览下一张。到最后一张即停止，即使网站轮播支持循环也不再点击；序号不变化、加载失败或找不到可用箭头时停止整轮。若初始停在中途，先用正常左箭头逐步回到第一张。浏览动作可能增加网站自身的图片请求，但不会按 URL 直接补下载。真正保存了多少仍以 images/index.json 为准，浏览全部图片不保证网络加载全部成功。

所有短等待、图片加载和评论操作都检查同一请求预算、时长与停止锁；一篇浏览结束后，仍按既定的 10–60 秒及 5% 长等待策略安排下一篇。

# 页面加载诊断

单篇评论验证可使用 `--test-once --test-expand-reply --no-browse-images --url "当前账号取得的笔记链接"`：只对已加载且有可用展开控件的评论展开一条回复，候选不足则不展开，不为寻找回复无限滚动；正常采集仍按 50%／25%／25% 抽样。此参数不能用于批量任务，也不解除停止锁。

单篇测试支持 `xhslink.com`／`xhslink.cn` 分享短链接，用当前浏览器跳转后直接复用页面；可加 `--expect-title "预期标题"` 防止误操作其他笔记。短链接测试归档位于本轮 `posts/shared_link/`，真实笔记 ID 写在 manifest.json 中；加载期间不移动目录，避免影响仍在完成的响应归档。

每轮归档根目录新增 `network.jsonl`，记录请求路径、类型、状态码、完成或失败及耗时；不记录请求头、Cookie、请求正文或 URL 查询参数。`load_diagnostics.json` 在关闭浏览器之前保存未完成请求清单、页面加载阶段和图片加载数量，避免把退出时的取消误当成最初原因。页面脚本异常与控制台错误会经过脱敏后记录。诊断只监听现有浏览器事件，不新增网络请求。

评论交互前等待当前笔记 `/api/sns/web/v2/comment/page` 首批响应完成，再确认主评论数量已渲染、加载提示消失、区域内容至少稳定 1 秒。明确返回空评论列表可判定为零条；只有容器可见或出现空壳不能判定加载完成。最多等待 20 秒，未确认完成就保存诊断并停止，不继续抽样、不将超时当作无回复。这只确认首批已加载评论，不滚动采集全部评论。加载结果随 interactions 写入运行报告。

打开页面、输入搜索词、按回车提交、搜索结果滚动、点击笔记、关闭详情和返回结果页前，各增加 1–5 秒随机等待；图片翻页和评论展开仍各有 1–5 秒等待。笔记之间／滚动轮次之间原有的 10–60 秒及 5% 概率附加 5–10 分钟等待继续保留。等待期间检查预算与停止状态。浏览器自身自动发送的资源请求不逐个延迟；这些操作间隔不构成已验证的安全频率。

导航超时仍停止当前轮次，不因 HTML 中有正文而认定页面可操作，也不自动重试或清除停止锁。图片缺失续采未修改，完整正文缓存仍按原规则跳过。
