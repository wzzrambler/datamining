# P4共指消解 V2

当前实现：P2完整实体＋独立Jieba词性候选＋领域与短语规则＋事件结构候选＋来源约束检索＋规则排序与拒绝。预测不读取人工标注，不训练或调用共指模型，不预设文档、段号、先行词区间或人工配对。

## 运行

在仓库根执行：

```powershell
python -m pip install -r requirements.txt
python "src/P4共指消解/run.py"
python -m unittest discover -s tests/P4 -v
python "src/P4共指消解/evaluate.py"
python "src/P4共指消解/compare.py"
```

run.py默认输入为P1正式原文、P2 V2及真实段落来源；验证P1/P2/来源哈希、文档集合和所有实体区间。--root支持新同结构数据根；--config覆盖通用配置。人工文件可以不存在或损坏，不影响预测。compare.py是独立开发核验入口，需要已冻结的V1对照，不是预测依赖。

## 算法与代码

1. core.py保留V1规则和V2调度；v2.py组织新版检测、实体与事件通道。sentences保留原文区间，中文句末、分号和换行切句；英文句点当前不作为句界。
2. tokenization.py使用独立Tokenizer/POSTokenizer，HMM=False。当前安装Jieba 0.42.1；记录版本、基础词典及注入词典SHA-256。注入当前文档P2实际出现的POI/交通完整原名及通用领域名词，不读取gold。字符位置按分词序列累计，包含空白、重复词和Unicode，不使用无界find。完整tokens另存tokenization.json。
3. P2完整提及始终直接入池。明确白名单n/ng/nr/nr1/nr2/nrj/nrf/ns/nt/nz/nl补充名词，使用相邻受限修饰词＋中心词、数量词＋量词＋动物/人物及地点附近后缀生成短语。词性不等于实体身份，普通抽象名词保留other，不能因n/nz而当POI；命名场馆内部动物词不制造独立动物。P2与未知同名词不擅自混并。
4. event_candidates.py基于动作/v类谓词、分句、逗号连接安排、动词补语、箭头及编号结构生成可回切的事件候选，保留否定和条件。完整结构最长600字符，不把截断文本当完整事件；过长结构记录generation_limits。事件通道不再因“这种安排”等表达直接提前返回。
5. 实体搜索同句和前两句、180字符；本地没有类型适配候选时，允许回看紧邻的同来源连续正文上一段。禁止跨文档、正文/图片/评论混接、不同图片/评论；legacy无细分来源不允许跨段；新标题/行程切换阻断。事件独立搜索最近两个结构末端，距离上限1200字符，每个候选完整长度仍不超过600。当前不支持跳过多段回溯整篇。
6. 实体评分为0.45*T+0.35*D+0.20*L。D=1/(1+字符距离/12)，L同句1、上一句0.5、其他0。T由类型适配决定；裸动物名降低为0.75，地点/设施泛称最高0.5。POI没有无条件压倒性加分；“他们”只有动物行为证据时才允许拟人。来源于同一确认entity_id的提及取最后有效位置，其他同名词保留。
7. 事件评分为0.50*结构适配+0.30*距离+0.20*连续性。路线/行程/段落与安排等中心词约束候选形态；正式版对明确焦点不匹配的候选拒绝。同一完整路线/安排可以覆盖其动作子候选；不同事件近分保留歧义。阈值0.65、最小分差0.10，分数不是概率。明确“两条路线”且恰有两个不重叠路线块时支持集合；其他复数不足时拒绝。

V2正式reference采用通用触发核心：这个/这种保留，条/座/只作为后续名词的量词分开；这一/这次/这段/这样等复合触发形式保留。完整名词性表达另存reference_phrase，原检测区间另存trigger。规则与gold无关，不能为了逐条对齐答案选择边界；这种统一规则仍会与少数人工边界冲突。句内谓词可为“这”提供地点/动物等类型线索；无法判断则未消解。篇章提醒仍单独处理。

## 输出和P6交接

- processed/P4共指消解/coreferences.json：schema p4-coreferences-2，含输入/程序哈希、配置、关联、候选来源、分项得分、检索层次、阻断及拒绝原因、基线和字符区间。
- tokenization.json：全部47篇分词、词性、偏移、词典元数据与过长事件诊断，含没有指代命中的文档。
- summary.json为自动统计，validation.json为结构校验，都不是人工准确率。
- outputs/P4/P4自动消解检查表.csv、P4消解文本_仅供检查.json和P4自动结果说明.md供核查；原文不覆盖。

每条记录统一有antecedents列表：单项一个、多个为集合、未消解为空。antecedent兼容字段仅单项时填写，多项/未消解均null。P6使用status=resolved的antecedents及来源/位置；未知普通名词只有文档局部candidate_id，不自动成为跨文档标准实体。检查文本按原文位置附注，不能当事实原文。

## 固定标注核验与阶段对照

人工原文JSON和CSV保持原样。evaluate.py只接受confirmed/user_confirmed的可判定行，校验P1及逐篇正文哈希、全部偏移、字段状态、单/多先行词互斥等。人工范围不受算法窗口限制，漏检、事件、长距离仍进入原分母。

严格匹配reference区间和先行词区间；多项要求完整集合一致。单先行词成功率和多先行词成功率分开；无分母为null。边界重叠仅作诊断，不计严格正确。未对齐的自动命中保持未知，不要求补标、不推断对错。

当前五篇51行中41目标、33单先行词（含14事件）、1多先行词。V1输出5关联、正确4；V2输出14、正确11、错误3。单先行词成功11/33，事件4/14，候选14/33，检测39/41。已对齐关联正确率78.6%，目标关联覆盖率34.1%；均为已见开发样本核验，不代表独立泛化准确率或全量76条关联的正确率。

compare.py保留V1和A名词/B事件/C窗口与边界/D评分拒绝的阶段配置、样本预测、逐行评估、代码/输出哈希；见outputs/P4/改进对照/P4改进对照.md。A—D使用同一最终源码及通用开关，是功能消融对照；V1为冻结的历史源码和结果。阶段结果包含退步，不只展示最佳数字。基线在当前相同检索边界内取最近P2，不使用补充名词、事件或类型评分，候选不同，不能把全部变化只归因于排序。

## 局限

仍不解决全部事件语义、后指、整篇概括、跨多段路线集合和所有普通动物/设施专名。当前设施和other样本严格成功仍为0；部分事件过宽、同名不同位置、边界冲突或候选来源受限会失败。明确双路线在合成测试通过，但现有真实多先行词样本仍失败。地点子集成功数低于当前最近P2基线，不宣称各类均优于基线。阈值和词表属于开发规则，未有独立留出验证。
