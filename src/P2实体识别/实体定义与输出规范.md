# 实体定义与输出规范

日期：2026-10-31。依据教师P2要求及用户确认的POI二分类。仅保留正式实现，按用户裁定采用核心时间边界；已核对第三方定性意见并修复，未将其冒充完整人工金标准。

## 1. 三类实体与POI角色

一级类型固定为`POI`、`TRANSPORT`、`TIME`。只增加一个字段`poi_role`区分两类POI：

| type | poi_role | 中文含义 | 纳入范围 |
| --- | --- | --- | --- |
| POI | attraction | 游览项目实体 | 具体景区、园区、景点、打卡点、展馆、可独立体验的命名游乐设施 |
| POI | support | 通勤与配套实体 | 具体交通站点、园区出入口、命名停车场、命名餐厅和命名酒店等 |
| TRANSPORT | 空字符串 | 交通方式 | 步行、徒步、自驾、打车、高铁、地铁、观光车及语境明确的游览交通工具 |
| TIME | 空字符串 | 时间表达 | 时刻、时段、时长、日期、日期范围、行程日序、相对时间 |

两类POI分别用于后续游览节点安排与接驳/就餐/住宿安排。support名称包含“通勤与配套”，因为餐厅、酒店也承担服务功能。

泛称不纳入POI，例如酒店、餐厅、车站、站点、入口、门口、停车场、景区、园区。具有明确园区语境的“北门”“南门”是可定位的局部名称，可纳入support；只有“门口”而无具体名称不纳入。

## 2. 跨类型与名称边界

- 景区、园区自身可为attraction；省市名称不作为本阶段POI输出。原文出现的外部具体景点可以保留，不强行视为当前景区内部地点。
- 酒店或餐厅即使命名与动物相似，也按设施用途归support，例如熊猫餐厅不能归熊猫游览项目。
- 剧场、影院等具体观演场所归attraction。节目、花车巡游、烟花秀等活动名称本身不自动视为地点；保留在原文供P3提取活动。
- 原文完整写出“海豚剧场”才匹配该实体，不把单独“海豚”补成剧场，也不在“白鲸、海豚、海狮三个剧场”中制造三个原文不存在的完整字符串实体。
- 长名称优先：“长隆野生动物世界北门”按完整support名称记录，不在同一区间再嵌套重复输出其父园区和北门。
- 不同位置的同一名称保留各自提及；别名归一化后才聚合统计，不能因去重而丢失位置。
- “珍珠滩”与“珍珠滩瀑布”、熊猫海与熊猫海瀑布保持独立。父区域与子地点不能当作别名合并。
- 地铁站是POI/support；“坐地铁”中的地铁是TRANSPORT。纯数字线路号不单独视作POI。
- 小火车、空中缆车兼有交通和体验功能：明确乘坐/换乘/接驳语境优先TRANSPORT；明确作为独立游玩项目介绍时可归POI/attraction。中性路线串等无法确定时进入歧义清单，不同一区间强制双标；小火车游览区是POI/attraction，具体缆车站是POI/support。
- 简称、笔误、OCR破碎词只在证据支持时归一化。词表保存原始写法与出处；不能静默把“双溪长隆站”等疑似错误写法改成其他站名。
- 中文时间、阿拉伯数字时间、英文单位都纳入；时间范围优先整体匹配。“第三站”属于步骤，不是TIME。

## 4. 输出结构

顶层对象含schema_version、input_sha256、config_version及documents。documents按输入顺序保存，每项含doc_id、scenic_code和mentions；没有命中时mentions为[]，仍保留文档记录。

每条mention字段：

| 字段 | 内容 |
| --- | --- |
| mention_id | 当前输入与配置版本内稳定且唯一的提及标识 |
| type | POI / TRANSPORT / TIME |
| poi_role | attraction / support；非POI为空字符串 |
| subtype | POI可为scenic/spot/ride/venue/station/gate/restaurant/hotel/parking/shop/service_center；TIME可为clock/clock_range/period/duration/interval/date/date_range/day_index/relative；交通可为mode |
| text | 原文中的实际字符串，不能用标准名替换 |
| para_id | P1段落i |
| start、end | 相对于全文content的字符偏移，零起点、右端不含 |
| canonical_name、entity_id | 有可靠依据时填写，未确定时为空字符串 |
| method、rule_id | 识别方式和命中依据，不伪造概率分数 |
| origin | 已有paragraph_sources条目列表；历史来源用kind=legacy标记，不推造图片或评论出处 |
| time_context | 可选：核心值之外的原始时间表达、全文start/end、prefix/suffix；不改变实体本身的位置 |

每条满足`content[start:end] == text`。doc_id/scenic_code在所属文档对象中保存，不要求每条mention重复。同名北门的entity_id需考虑所属园区；仅凭GZCL不能区分野生动物世界北门与欢乐世界北门。

时间子类型统一：时刻范围为clock_range（10:00–20:30），不是单点clock或日内period；12月初是约略date，日期范围需有两端；重复间隔为interval。按用户裁定取核心值：提前半小时取半小时/duration，23:59前取23:59/clock，30分钟一场取30分钟/interval；原提示词记录time_context。今天/明年等自身有相对意义的表达仍为relative。duration可含时长范围。POI的shop用于明确命名的商店，不把便利店误归restaurant。

游乐设施即使使用船、车并可“乘坐”，也不因此变为通勤交通。例如海底互动船以固定游乐项目归POI/attraction；跨酒店、园区接驳的小船则是TRANSPORT，不能只以“乘坐”一词机械判断。

以上是P2的新输出规范，P1字段和正文不变。JSON是主要交接文件，扁平表作为检查辅助；词频按提及次数和文档频次分别统计，POI再按poi_role分组。

1. 覆盖阅读三景区全部47篇，重点归纳路线、项目介绍、交通、住宿和就餐段；正文内已纳入的OCR和作者评论同样参与。
2. 每个词条保存原词、类型、POI角色、至少一处doc_id/para_id证据及必要的上下文约束。
3. 泛称、活动、城市、疑似OCR错误、不能定位的别名分别列入排除或待核对清单。
4. 同名异地、父子地点和双功能设施单独检查，形成正式词典。
5. 全量原文参与词表设计，评测据实称为固定语料内验证；P1的人工抽查结论不转用为P2标注结果。
