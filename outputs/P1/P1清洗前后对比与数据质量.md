# P1：清洗前后对比与数据质量验证

数据版本：2026-10-31。本文可作为实验报告P1的“预处理结果”“清洗效果对比”“数据质量验证”和“问题与处理”部分。人工抽查结论依据已确认的抽查表；自动检测结果依据当前正式数据重新计算。

## 1. 数据规模与处理流程

本阶段保留原有微信公众号及景区官方网站的17篇数据，新增30篇小红书游客游记，整合形成47篇景区文本。其中，官方推荐路线6篇，游客游记41篇；清洗后共100222个字符、4820段。字符数按Python字符串长度统计，包含标点和换行，不是分词后的词数；当前段落由正文换行划分，不等同于完整语义段落。

| 景区 | 官方推荐路线 | 游客游记 | 合计 |
|---|---:|---:|---:|
| 广州长隆旅游度假区 | 3 | 15 | 18 |
| 珠海横琴长隆国际海洋度假区 | 2 | 13 | 15 |
| 九寨沟风景名胜区 | 1 | 13 | 14 |
| 合计 | 6 | 41 | 47 |

三个景区均达到任务书检查步骤中“至少1条官方路线和3篇游记”的最低要求，游客游记数量也达到每景区5篇。不同来源的数量不完全均衡，后续官方与游客文本比较时需要考虑这一差异。

小红书采集使用浏览器自动化保存实际收到的网页或JSON响应、渲染HTML、图片及已加载评论；清洗阶段读取本地归档，依次处理作者正文、按图片顺序排列的OCR文字、已采集的作者评论。作者正文不设30字门槛；每张图片和每条作者评论在清洗后，只有汉字、字母、数字合计严格大于30个字符时才进入正文，并进行文档内行级去重。原始OCR响应、评论记录以及未纳入内容单独保留，便于追溯。

| 新增数据组成 | 处理数量 | 最终向正文贡献内容的数量 |
|---|---:|---:|
| 作者正文 | 30份 | 30份 |
| 图片OCR | 324张 | 112张 |
| 已采集评论及回复 | 626条 | 56条作者评论 |

未贡献正文的部分可能未达到长度门槛、属于非作者评论或与前文重复，具体原因保存在清洗明细中。626条是本地已采集评论数量，不表示取得笔记的全部评论。

## 2. 关键清洗规则

清洗程序批量读取原始记录，处理残留HTML标签、网址、联系方式、不可见字符、表情和话题标记；统一空白、换行、全角字符与时间格式，清理重复行。规则保留景点名称、时间、价格、条件词和路线顺序等后续知识抽取需要的信息。

小红书方括号表情采用已知名称匹配，兼容`R`后缀，例如`[打卡R]`、`[笑哭R]`；正常方括号说明不会因外观相似而一律删除。附加文字的30字门槛在清洗后计算，避免表情名称被误计为有效文字。

原17篇以原组清洗结果为基础，对正式副本统一全角ASCII及空格，并重建段落和派生计数，原始历史文件不改写。新增30篇采用当前小红书处理流程。两部分现已统一格式、句数与净缩减量口径，来源抽取和去噪流程仍各有区别，不将其描述为完全相同的清洗算法。

## 3. 清洗前后代表性对比

以下均为本地正式数据中的真实片段，片段清洗效果不代表整篇正文只包含这些内容。完整逐部分记录见`辅助资料/raw_and_clean_parts.json`。

### 3.1 去除表情并保留景点名称

来源：`ZHCL-NOTE-06`，作者正文。

清洗前：

```text
[打卡R]鲸鲨馆
```

清洗后：

```text
鲸鲨馆
```

处理结果表明，平台表情占位符得到删除，景点名称被保留。该文字属于作者正文，不因单行较短而被删除；图片和评论的长度门槛也不应用于正文中的每一行。

### 3.2 去除话题标签，保留时间与不确定性说明

来源：`GZCL-NOTE-07`，作者正文片段。

清洗前：

```text
表演：我之前问是 11:30和15:30，时间可能调整，建议问一下工作人员。
也欢迎大家评论区补充更多建议👇
#广州长隆[话题]# #长隆带娃攻略[话题]# #长隆野生动物世界[话题]# #熊猫酒店[话题]# #亲子游[话题]# #带娃旅行[话题]# #长隆避坑[话题]# #带娃去哪儿玩[话题]# #长隆[话题]#
```

清洗后：

```text
表演:我之前问是 11:30和15:30,时间可能调整,建议问一下工作人员。
也欢迎大家评论区补充更多建议
```

话题与表情被去除，时间和“时间可能调整”等限定语得到保留。清洗只整理文本，不将游客记述转换为已经核实的景区现行安排。

### 3.3 统一格式，保留路线方向

来源：`GZCL-NOTE-06`，作者正文片段。

清洗前（两行之间还包含空行及制表符）：

```text
导航：长隆野生动物世界北门｜停车36元/天

📍最优游玩路线：北门进 → 南门出，全程不走回头路，动线超顺滑！
```

清洗后：

```text
导航:长隆野生动物世界北门|停车36元/天
最优游玩路线:北门进 → 南门出,全程不走回头路,动线超顺滑!
```

空白行、制表符及装饰性表情得到清理，冒号和竖线等全角字符按当前规则转换为半角；停车价格、入口与出口，以及表示方向的`→`保留，避免破坏后续路线抽取。

### 3.4 附加文本按规则纳入，原始记录不丢弃

来源：`GZCL-NOTE-06`，一条作者评论。

清洗前：

```text
一日路线整理在图片上，大家可以收藏起来，去玩的时候拿出来跟着走
```

清洗后：

```text
一日路线整理在图片上,大家可以收藏起来,去玩的时候拿出来跟着走
```

该评论清洗后包含29个有效字符，未超过30，因此不进入正式正文，原始评论和清洗结果仍保存在辅助资料中。

作为对照，`GZCL-NOTE-07`的一条作者评论清洗后包含37个有效字符，内容如下，最终纳入正文：

```text
我看我的收货地址是在长隆度假区南大路收费口,外卖小哥一般会给放在美宜佳便利店
```

长度门槛能够减少短评论和互动文字，但不能单独证明语义质量，也可能排除简短的有效建议。因此，未纳入内容保留原件，后续可根据任务调整规则并重新生成结果。

## 4. 自动数据质量检测

对全部47篇执行字段集合与类型、编号唯一性、景区与文本类型对应关系、日期格式、来源链接、缺失值、重复内容及正文统计检查。逐值比较JSON、文档CSV、段落CSV和Excel中的对应数据，核对段落编号、连续字符位置和正文重组结果。

原始证据检查覆盖新增30篇笔记、324张已保存图片、626条已保存评论，并核对图片SHA-256与OCR记录的对应关系；同时检查47篇文档引用的原始HTML是否存在。检测全程离线，未重新请求网站或OCR服务。

### 4.1 结构与噪声检查结果

| 检查内容 | 检测结果 |
|---|---|
| 字段集合、类型、编号、段落位置 | 未发现结构硬错误 |
| JSON、CSV、Excel对应值 | 一致 |
| 新增段落来源映射 | 覆盖完整，未发现缺失、重复或越界 |
| 原始证据及图片哈希 | 检查通过 |
| HTML标签、网址、邮箱、疑似电话号码 | 按现有规则未检出残留 |
| 已知及疑似表情、话题标记 | 按现有规则未检出残留 |
| 控制字符、替换字符`�`、异常空白、连续重复标点 | 按现有规则未检出残留 |
| 独立网页控件文字、疑似模板元数据 | 按现有规则未检出残留 |

以上结果表示在已实现检测规则的范围内没有命中相应问题，不等于证明文本完全无噪声或OCR全部正确。

### 4.2 缺失值与异常字段

| 字段 | 缺失文档数 | 处理方式 |
|---|---:|---|
| 标题 | 1 | `GZCL-NOTE-11`在现有记录及原始HTML中均未取得标题，留空并标记 |
| 作者 | 0 | 保留原始记录 |
| 发布日期 | 3 | 原17篇中的缺失值暂保留，不推测补造 |
| 采集时间 | 17 | 原17篇缺少该字段值，不以迁移或清洗时间代替 |
| 正文、来源链接、原始HTML路径 | 0 | 保留来源及证据对应关系 |

空字符串与`null`不同。正式JSON没有`null`并不意味着没有缺失值，本次按空字符串另行统计缺失。

旧版`GZCL-NOTE-01`和`GZCL-OFF-01`的`noise_char_removed`分别为-2和-4。已将正式结果统一为`max(0, raw_char_len-clean_char_len)`，两处负值修正为0；该字段表示非负净缩减量，不是实际删除字符次数。历史原件保留旧值，转换记录单独保存。句数同时按中英文句末标点、分号和换行统一重算，避免半角转换后漏计句末标点。

### 4.3 重复内容检查

对全部47篇的1081个文档对执行重复候选检测，包括编号、来源链接、规范化正文完全重复、三字符集合Jaccard相似度以及包含关系检查。公众号文章保留标识文章的查询参数，避免将共用`/s`路径的不同文章误判为同一来源；小红书同一笔记的不同访问参数不作为不同身份。

近重复候选阈值为Jaccard相似度不低于0.8；两篇较短文本也至少包含200个规范化字符，且三字符集合包含率不低于0.9时，列为包含关系候选。本轮未发现整篇完全重复、近重复或包含关系候选。

跨文档段落检测发现1处相同文本：`ZHCL-NOTE-04`与`ZHCL-NOTE-05`均含有“The Operating Hours Are Subject To On-site Announcements.”，属于营业时间以现场公告为准的公共提示。该结果不能证明两篇文章整体重复，因此保留原文，并在重复候选中记录。

### 4.4 OCR及分段复核线索

324张图片共返回3646条OCR结果，其中3588条文本非空；599条非空行的识别得分低于0.8，最终纳入正文的图片中包含470条此类低分行。83张已纳入图片至少含一条低分行。识别得分不是经过校准的正确概率，不能据此计算OCR准确率。

另外，16篇文档中不超过10个字符的段落占比达到50%。短段落可能是正常景点名、时间、标题，也可能来自OCR断行。当前仅记录复核线索，不按长度直接删除，也不自动拼接，以免错误连接不同栏位或改变游览顺序。

原17篇此前存在2677个全角ASCII范围或相关空白字符，已在正式副本中按一对一映射统一为半角。转换保留中文、路线箭头、换行和内容顺序，正文总字符数与段落数不变；重新检查未检出该规则覆盖的全角格式残留。历史原件和新增30篇正文均保持不变。

## 5. 人工抽查

每个景区选取1篇官方路线、2篇游客游记，共9篇，占47篇的约19.1%。游客游记兼顾正文占比较高和图片文字占比较高的记录，检查误删、漏删、OCR文字与顺序及景区相关性。

| 景区 | 官方路线 | 游客游记 | 抽查结论 |
|---|---|---|---|
| 广州长隆 | GZCL-OFF-01 | GZCL-NOTE-07、GZCL-NOTE-11 | 3篇通过 |
| 珠海长隆 | ZHCL-OFF-01 | ZHCL-NOTE-06、ZHCL-NOTE-13 | 3篇通过 |
| 九寨沟 | JZG-OFF-01 | JZG-NOTE-04、JZG-NOTE-11 | 3篇通过 |

依据人工确认，本次9篇抽查在误删、漏删、OCR错字及顺序、内容相关性四项中均未发现影响使用的问题，记录为“通过”；抽查人栏按要求留空，日期为2026-10-31。已知的元数据缺失仍按上表保留。

该结论来自格式统一前的用户确认。此次仅等价格式转换及派生统计调整，已自动核对转换映射、新增正文不变和证据对应关系，没有新增人工抽查或改写原抽查表。抽查没有逐字标注支持，不能扩展为全部47篇的准确率、全量OCR准确率或无噪声保证；自动检测清单中的其他复核提示也未因此被批量关闭。

## 6. 结果输出与复现

正式结果存放于`processed/P1爬虫数据清洗/`：

- `documents.json`：合并47篇的完整正文、段落及元数据，作为后续阶段的主要输入。
- `new_documents.json`：新增30篇小红书记录。
- `dataset.xlsx`：文档清单、正文、段落及字段说明。
- `documents.csv`：文档元数据，不包含完整正文；`paragraphs.csv`保存逐段正文和字符位置。
- `辅助资料/`：原始OCR响应及缓存、原始评论、清洗明细、编号映射和段落来源。
- `质量检查/自动质检/`：质量检测报告、问题明细、重复候选、清洗对比及已确认的人工抽查记录。

最终JSON沿用原组字段，不新增业务字段。正文`content`为最终段落文本以换行连接的结果，段落位置基于最终正文重新计算。输出结构检查通过，能够作为后续实体识别等阶段的输入；OCR语义断行仍作为已知边界保留。

在仓库根目录可执行：

```powershell
# 全量自动质检与本地原始证据检查；结果写至指定目录
python tools/quality_p1.py --deep --output .test_tmp/p1_quality_recheck

# 正式数据与历史基线检查
python tools/verify_p1.py --deep

# 离线回归测试
python -m unittest discover -s tests/P1 -v
```

上述命令不启动浏览器或OCR服务。`--deep`需要本地原始归档；不加该参数可以执行不依赖大归档的结构与文本检查。新输出目录会生成新的待填人工抽查表，不应覆盖或替代已经确认的抽查记录。
